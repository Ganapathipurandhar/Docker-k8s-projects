# kubectl logs

k logs -n <namespace-name> <pod-name>
k logs -n <namespace-name> <pod-name> -all-containers # if you have multiple-container or replica of pods
it give all the logs in the all the containers, if you want to see the logs from specific containers

k logs -n <namespace-name> <pod-name> -all-containers -o=jsonpath='{{.spec.containers}}' # it give the logs but it hard to read to we can convent to json format "jq"
k logs -n <namespace-name> <pod-name> -all-containers -o=jsonpath='{{.spec.containers}}' | jq
now we can see all pods, now use '-c' we can specific the container name [multiple container in the pod]

k logs -n <namespace-name> <multi-container-name> -c nigix-container

## Kubectl port-forwarding
it is usefull when you want to access internal cluster resourse from within your local network without need of having expose the service to the internet
it is useful in test phase or this services not ment to be expose to internet 

k get svc -A # select the service with interal custerip 

k port-forward -n uat svc/note-app-deployment 8000:80 [8000 is my computer, 80 is pods port]

k get svc -n uat svc/note-app-deployment -o yaml
curl localhost:8000 # to access the service

other services
k port-forward -n kubernetes-dashboard kubernetes-dashboard-web 8000:8000
in local brower : http://localhost:8080

## kubectl auth can-I

it falls under RBAC, it use to conform wether I can access or not 

k auth can-i list pod -n monitoring --> yes 

for current use : k auth whoami 
for roles : k auth roles
k get role pod-reader -o yaml
k get rolebindings
k get rolebinding <name-of-rolebinding> -o yaml
k auth can-i get pod --as=jane ---> yes
k auth can-i delete pod --as=jane ---> no
k auth can-i get pod --as=system:serviceaccount:default:default ---> yes
k auth can-i delete pod --as=system:serviceaccount:default:default ---> no

verbose --v=1..10
k auth can-i get pod --as=jane --v=10 # it will give the more information about it
